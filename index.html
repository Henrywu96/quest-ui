Two sites, one system

My portfolio and Quest Town started from the same coral, navy and sky, then drifted apart one quick tweak at a time. In October 2026 I audited the code of both.

The same colour had a different name on each site, each site had grown its own set of font sizes, and some text was too faint to read comfortably. Quest UI keeps the look and gives every value one name.

Foundations

Everything here is drawn from tokens.json, the same file that builds the CSS. Select a name to copy its CSS variable.

Colour

Seventeen colours. Coral 500 is for pictures and big shapes; text and buttons use the darker coral 600.

What each colour is for

Components ask for a role, such as body text or card surface, and each role points at one colour. Changing what a role points at changes it everywhere.

Contrast, checked on every build

Text needs 4.5:1 against its background; large text and focus rings need 3:1. If any pair below drops under its minimum, the build stops before it writes the CSS.

Type

Fredoka for headings, Inter for everything else. Nine sizes, from 11px badges to the 64px page title.

Use it in a project

  1. Download the files

    The tokens and the components are two small CSS files. The JSON holds the same values for scripts and for Motion springs.

    quest-ui.css components.css tokens.json

  2. Load them once

    @import "./quest-ui.css";
@import "./components.css";

  3. Build with the names

    .quest-log {
  padding: var(--qu-space-6);
  border-radius: var(--qu-radius-xl);
  background: var(--qu-surface-card);
  color: var(--qu-text-body);
  box-shadow: var(--qu-shadow-md);
}

  4. Change a value in one place

    Edit tokens/tokens.json and run npm run tokens. The build checks every contrast pair first, then writes the CSS and this page's data. The same names are set up as variables and styles in Figma, so designs and code pick from one list.
